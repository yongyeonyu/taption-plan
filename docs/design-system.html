규칙 C1 — 미확인이 이 시스템에서 가장 중요한 상태인 이유

2.2Typography

먼저 고칠 것 — Font.taption이 조용히 +2pt 한다

static func taption(size: CGFloat, weight: Font.Weight = .regular) -> Font {
    .system(size: size + 2, weight: weight)  // ← 9를 쓰면 11이 된다
}

621곳이 호출한다. .taption(size: 9)는 11pt로, .taption(size: 11)은 13pt로 렌더된다. 코드를 읽는 사람은 실제 크기를 알 수 없다. 이게 41개 실제 크기가 27개로 집계된 이유다.

처리: @available(*, deprecated, message: "Font.tpLabel / tpCaption … 사용. 이 API는 +2pt")를 붙이고, §2.2.4 매핑표로 일괄 치환한 뒤 삭제한다. 호환 레이어를 남기지 말 것 — 남기면 진실이 두 벌이 된다.

왜 이 숫자들인가

tpLabel 12가 한글 하한. 11pt는 Apple의 절대 하한이지만, 한글 음절은 평균 18획이라 11pt에서 분류·센서의 가로획이 뭉개지기 시작한다. 12pt가 실측으로 버티는 가장 가까운 칸이다(음절 advance 10.38pt, 획 간격 ≥1.4pt).

tpBody 15이고 16/17이 아닌 이유. 한글 15pt의 시각 무게 ≈ 라틴 17pt(음절 0.865em vs 라틴 소문자 평균 0.5em). 17을 쓰면 화면 전체가 "너무 크게 말하는" 느낌이 되고, 고양이·정원의 톤과 싸운다.

tpMetric 26. 6시간 12분이 26pt에서 90.5pt 폭 — 2열 지표 카드(각 ~160pt)에 들어간다. 34pt면 118pt라 1열만 가능하다.

세 개의 숫자 급이 11pt 미만인 것은 의도적이고, 규칙으로 못 박혀 있다. 눈금의 09:30은 라틴 숫자다. 숫자는 9pt에서도 읽힌다. 한글은 아니다.

SwiftUI 표현 · Dynamic Type

지금 앱 전체가 Dynamic Type 지원이 0이다. .system(size:)는 절대값이라 시스템 글자 크기를 따라가지 않는다. @ScaledMetric은 1,077개 호출점의 구조를 바꿔야 하니, 정적 팩토리 하나로 해결한다.

enum TaptionType { struct Spec { let size: CGFloat let weight: Font.Weight let relativeTo: UIFont.TextStyle /// 고정 높이 컨테이너의 크기는 반드시 상한을 둔다. 안 그러면 트랙을 뚫는다. let maxScale: CGFloat } static let body = Spec(size: 15, weight: .regular, relativeTo: .body, maxScale: 3.0) static let label = Spec(size: 12, weight: .semibold, relativeTo: .caption1, maxScale: 1.8) static let ruler = Spec(size: 9, weight: .semibold, relativeTo: .caption2, maxScale: 1.35) // … 12개 } extension Font { static func tp(_ s: TaptionType.Spec) -> Font { let m = UIFontMetrics(forTextStyle: s.relativeTo) let scaled = min(m.scaledValue(for: s.size), s.size * s.maxScale) return .system(size: scaled, weight: s.weight, design: .rounded) } static var tpBody: Font { tp(TaptionType.body) } }

.rounded는 강제다. 이 제품의 "따뜻함"을 만드는 주된 축 중 하나다 — 506곳 중 287곳이 이미 쓰고 있고, 나머지 219곳이 누락이다. "모던하게" 보이려고 기본 SF Pro로 바꾸면 즉시 기업 대시보드가 된다.

규칙 T1 — maxScale이 무한이 아닌 이유

타임라인의 트랙 높이는 GeometryReader가 계산하고 verticalInset = 28은 상수다. 글자만 3배가 되면 라벨이 서로 눌린다.

그래서 tpRuler/tpMeter의 maxScale은 1.35로 잠근다. AX1을 넘으면 시간축은 글자를 키우는 대신 3개 lane을 1개로 접는다(§5.1). 숫자는 영원히 보조이고, 이름이 정보이기 때문이다.
