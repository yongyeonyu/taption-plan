# 정확도 올리기 — 검토와 제안 (ACC1114A01, 2026-11-14)

대표 지시: 「우리 앱의 알고리즘이랑 카카오 지도의 API를 최대한 활용해서 정확도를 최대한 올리고 AI를 활용해서 정확하게 보정할 수 있게 전체를 검토한 다음에 제안」. 코드 읽기로 검토했고(실측 아님), 줄 번호는 2026-11-14 main 기준이다. 대표 기록에서 나온 가게·동네 이름은 적지 않는다.

## 1. 지금 구조에서 틀리는 이유

분류는 `AppModel+Classification.swift`의 `performSensorTimelineRefresh`가 순서대로 한다: 움직임 기록 → 체류(70m·15분) → 등록 장소 붙이기 → 이동 구간·탑승 결정 → 지하철·차·버스 판별 → 체류 문맥(집에서 휴식 등) → 활동 분류 → 빈 시간 메우기 → 이름 맞추기(지하철·버스·장소 이름·결제).

| # | 약한 곳 | 결과 |
|---|---|---|
| 1 | 잠금 물려받기: 새 기록이 잠긴 기록과 짧은 쪽 기준 20% 겹치면 잠긴 기록의 분류·이름을 물려받는다(`TaptionActivityEngineAdapter` 1627·1806) | 긴 「집에서 휴식」 안의 짧은 외출이 모두 휴식이 된다. 잘못 잠긴 판정이 고쳐지지 않는다 |
| 2 | 등록 장소 반경 200m + 체류 70m·15분 | 집 근처 가게·병원이 집으로 묶인다. 15분 안 되는 방문은 체류가 아니다 |
| 3 | 가계부가 분류에 쓰이지 않았다 | 결제라는 가장 강한 근거를 버렸다 → **PAY1114A01로 넣음** |
| 4 | 입력이 같으면(지문 같음) 이동 마무리·이름 맞추기를 건너뛴다(369~399줄) | 나중에 도착한 정류장·노선·카카오 이름이 지난 시간에 반영되지 않는다 |
| 5 | 정류장·노선 기억이 구간 시작·끝 「분」 열쇠이고 기기에만 있다 | 구간 경계가 1분 움직이면 못 찾는다. 오늘 구간만 조회한다 |
| 6 | 분류 이름 불일치: 앱이 기록에 `eating`·`housework`·`shower`를 쓰는데 AI가 그대로 보내면 거절 | AI 교정이 `unknown_category`로 실패 → **받도록 고침** |
| 7 | AI 공유 「요약」 단계에는 이동 구간 번호가 없다 | AI가 이동 수단을 고칠 수 없다 |
| 8 | AI 명령에 기록 나누기·머문 곳 정하기가 없고, 이동 수단에 자전거·배·택시가 없다 | AI가 볼 수는 있어도 고칠 수 없는 것이 많다 |
| 9 | 카카오 이름은 이름 없는 체류에만, 식당만 활동으로 옮긴다 | 병원·카페·마트는 이름만 붙고 분류는 그대로 → 결제가 있으면 PAY1114A01이 옮김 |
| 10 | 사용자 교정이 기록 번호에 묶이는데 번호가 구간 경계에서 나온다 | 체류 경계가 움직이면 교정이 떨어진다 |

## 2. 제안 (효과 큰 순)

### A. 근거를 더한다
- **A1 결제 확정(넣음, PAY1114A01)**: 이름 없는 체류 안의 결제 → 그 가게·활동. 「집에서 휴식」 안의 결제 + 앞뒤 10분 걸음 → 그 시간만 외출로 떼어 냄. 가게 종류 → 대분류(의원·약국 → 건강, 식당 → 식사, 카페 → 휴식, 마트 → 일상).
- **A2 결제 가게 좌표 확인**: 결제 가게 이름을 카카오 키워드 검색(`/kakao/keyword`, 그날 지나간 자리 반경 300m)으로 찾아 좌표를 얻는다. 맞으면 그 자리를 그 가게로 확정하고, 300m 안에 없으면 온라인 결제로 보고 쓰지 않는다. 지금의 「걸은 흔적」 조건보다 정확하다.
- **A3 체류 후보 넓히기**: 카카오 분류 코드 전체를 활동으로(병원·약국 → 건강, 문화시설·관광 → 취미, 마트·편의점 → 일상, 학교·학원 → 공부). 후보가 하나뿐이고 30m 안이면 결제가 없어도 분류를 옮긴다(확신 「보통」).
- **A4 짧은 방문 잡기**: 체류 기준(15분) 아래라도 결제가 있으면 방문으로 만든다(A1의 떼어 내기를 「이동 중 정지」에도 적용).
- **A5 버스 노선(넣음, 키·배포 끝)**: 승하차 정류소를 함께 지나는 노선. 기기에서 `bus_route_lookup` 확인이 남았다.

### B. 잠금이 고침을 막지 않게 한다
- **B1 근거 있는 새 판정이 잠금을 이긴다**: 결제·사용자 확인·노선 근거가 붙은 기록은 잠긴 기록의 이름을 물려받지 않는다(`freshWins`에 조건 하나).
- **B2 물려받기 조건 좁히기**: 짧은 쪽 20%가 아니라 「잠긴 기록이 새 기록의 80%를 덮고 길이가 비슷할 때」만.
- **B3 늦게 온 근거 다시 반영**: 정류장·노선·카카오 후보·가계부가 바뀌면 그날 이름 맞추기를 다시 돈다(지문에 이 값들의 판 번호를 넣는다).
- **B4 기억을 저장소로**: 정류장·노선·장소 후보를 기기 설정이 아닌 앱 저장소에, 열쇠는 5분 칸 + 위치 칸으로.

### C. 묻고 확정한다 (대표 지시 「버스도 지하철처럼 정류소 물어보고 확정」)
지금 탑승 확인(`TransitBoardingCandidateEngine` → 확인 시트 → `TransitBoardingDecision`)은 「이 역에서 탔나요」만 묻고 노선은 묻지 않으며 오늘만 묻는다.
- **C1 버스**: 차량·버스 구간의 승하차가 정류소면 「○○ 정류소에서 버스를 탔나요?」 + 노선 고르기(두 정류소를 함께 지나는 노선, 없으면 탄 곳 노선 전체) + 「버스 아님(내 차·택시)」. 답은 `TransitBoardingDecision`에 노선·정류소와 함께 저장하고 근거 「사용자 확인 · 버스 탑승」·「노선 80」으로 남긴다(되돌림 규칙이 건드리지 않는다).
- **C2 지하철**: 같은 시트에 탄 역·내린 역·노선을 보여 주고 고칠 수 있게.
- **C3 기차·배·비행기**: 역·항구·공항에서 시작·끝난 긴 이동에 「기차/배/비행기를 탔나요?」.
- **C4 자전거**: 장소가 아니라 구간에 묻는다 — 속도가 자전거 범위이고 걸음이 없는 구간에 「자전거를 탔나요?」.
- **C5 지난 날도**: 오늘만이 아니라 답하지 않은 최근 7일을 할 일 목록 「확인」 탭에 모은다.
- **C6 AI 검토**: 같은 질문을 AI 일(`AITask`)로도 만든다 — AI가 그날 결제(교통 카드·통행료)·일정·평소 패턴을 보고 답을 제안하고, 확신이 없으면 `askUser`로 대표에게 묻는다.

### D. AI가 고칠 수 있게 한다
- **D1** 요약 단계에도 이동 구간을 번호·수단·시각만(장소 이름 없이) 준다.
- **D2** 명령 추가: `splitRecord`(기록 나누기), `setStayPlace`(머문 곳 가게·분류 정하기, 후보 번호로), `answerBoarding`(탑승 질문 답하기), 이동 수단에 자전거·배·택시.
- **D3** `get_activity`에 근거를 싣는다: 기록마다 「근처 후보」·「결제 확인」·확신 단계, 받는 분류 번호 목록.
- **D4** 교정 열쇠를 시간 겹침으로도 찾는다(경계가 움직여도 교정이 남게).
- **D5** 하루 끝 검토 일: 확신 「보통」 이하·미확인·근거 충돌(결제 가게와 체류 이름이 다름)을 묶어 AI에게 넘기는 일을 만든다.

## 3. 카카오 지도를 오픈맵과 같은 화면으로 (대표 지시)

오픈맵은 지도·경로선만 지도가 그리고, 핀·화랑이·말풍선·안개·사진·날씨는 모두 지도 위 SwiftUI 층(`MapHomeVectorViewportOverlay`)이 화면 좌표로 그린다. 따라서 카카오 지도를 「좌표 → 화면 점을 계산해 주는 엔진」으로 만들어 같은 층을 올리면 같은 화면이 된다(핀을 카카오 기호로 다시 만드는 것보다 훨씬 싸고, 화랑이 움직임·말풍선이 그대로 나온다).

| 단계 | 내용 | 끝난 기준 |
|---|---|---|
| K1 | 화면 점 계산: 카메라가 움직이는 동안 매 화면마다 세 모서리의 지도 좌표를 읽어 변환식을 만들고 `MapHomeVectorViewport`를 낸다. 같은 층을 올린다 | 지도를 끌면 모든 핀·화랑이가 붙어 다닌다 |
| K2 | 카메라 명령: 현재 위치·날짜 이동·나침반 따라가기 | 하단 「현재 위치」·「집」이 같게 동작 |
| K3 | 손동작: 누르기(핀 고르기)·길게 누르기(메뉴)·끌기 시작/끝 | 메모·핀을 눌러 열 수 있다 |
| K4 | 재생: `MapHomePlaybackSink` 구현(카메라·화랑이·발자국) | 재생이 오픈맵과 같다 |
| K5 | 경로선 색·점선·지하철 색, 로고 자리 | 선 모양이 같다 |

위험: 카카오 SDK에 「좌표 → 화면」 함수와 「카메라 움직이는 중」 알림이 없다. 세 모서리로 계산하는 방식은 지도를 기울이면 틀리므로 기울이기를 끈다. 화면 층이 지도보다 한 화면 늦게 따라와 끌 때 떨릴 수 있다(K1에서 먼저 확인). 계절 색·지도 글자 언어 바꾸기는 카카오에서 안 될 수 있다.

## 4. 순서 제안

1. B1·B3 (잠금·늦은 근거) — 지금 넣은 결제·노선·장소 이름이 지난 시간에도 반영되게 하는 바탕.
2. C1·C5 (버스 탑승 확인, 지난 날 포함) → C2~C4.
3. A2·A3·A4 (결제 가게 좌표 확인, 분류 넓히기, 짧은 방문).
4. D1~D3 (AI가 읽고 고칠 수 있게) → C6·D5 (AI 검토 일).
5. K1~K5 (카카오 지도 동일 화면)은 정확도와 별개라 나란히 진행.
