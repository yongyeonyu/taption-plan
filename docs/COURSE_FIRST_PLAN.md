## 2. 바뀐 흐름

1. 여행을 만들면 계획표 판이 **코스**로 열린다(여행 중이 아니어도).
2. 코스에서 「곳 더하기」 → 장소를 찾아 고른다 → 그날 코스 끝에 붙는다. 시각은 앱이 잡는다.
3. 목록에서 끌어 순서를 바꾼다. 시각은 순서대로 다시 잡힌다.
4. 필요한 곳만 눌러 **세부 계획**을 적는다(그 곳 안의 할 일, 정확한 시각, 메모, 예상 지출).

원칙: 코스에서 한 것과 계획표에서 한 것은 같은 일정이다. 화면만 둘이고 저장은 하나다.

## 5. 단계

각 단계는 따로 커밋하고, 단위 시험 → 시뮬레이터 화면 시험(사진) → 아이폰 11 Pro 시험 순으로 확인한다. `TravelModeView.swift`는 1,200줄 한도라 새 코드는 `TravelModeSupport.swift`나 새 파일에 둔다(새 파일은 `project.pbxproj` 등록).

### C1. 코스를 기본으로 (작음)
- 날짜가 있는 여행은 계획표 판이 코스로 먼저 열린다. 고른 탭은 여행별로 기기에 기억(`@AppStorage`).
- 일정이 하나도 없는 날: 「첫 곳을 더해 보세요」와 「곳 더하기」 단추.
- 파일: `TravelModeView.swift`(기본값), `TravelModeSupport.swift`(빈 화면).
- 시험: 기본 탭 고르기 계산, 화면 시험(새 여행 → 코스).

### C2. 코스에서 곳 더하기 (중간) — 「지도 검색으로 일정 만들기」를 이것으로 대신한다
- 코스 목록 맨 아래 「곳 더하기」 → 장소 검색(지금의 `TravelPlacePicker`를 넓힘: 여행지 둘레 먼저, 결과에 종류 짐작 — 식당 → 식사, 숙소 → 숙소, 그 밖 → 관광).
- 고르면 편집기를 거치지 않고 바로 그날 끝에 붙는다. 이름 = 장소 이름, 장소 붙음, 시각은 D2.
- 장소 없이 이름만으로도 더할 수 있다(「직접 쓰기」).
- 방금 더한 것은 되돌리기(↶)에 쌓인다.
- 새 계산 `TravelCoursePlanner.nextSlot(…)`: 그날 일정·종류 기본 길이·이동 분(있으면)으로 시작과 끝을 낸다. 자정을 넘기면 23:45까지로 줄이고 알림 한 줄.
- 파일: `TravelModeSupport.swift` 또는 새 `TravelCourseEditing.swift`, `TravelPlacePicker.swift`, `TripImportSheet.swift`(`addTripItem` 그대로 씀).
- 시험: `nextSlot` 경우들(빈 날, 오늘, 이동 시간 있음/없음, 하루 끝), 화면 시험(곳 두 개 더하기).

### C3. 순서 바꾸기와 지우기 (중간)
- 코스 목록에서 길게 눌러 끌어 순서 바꾸기, 밀어서 지우기(되돌리기 가능).
- 순서가 바뀌면 D3 규칙으로 시각을 다시 잡는다. 예약된 곳·시각을 직접 고친 곳은 「고정」으로 보고 건너뛴다. 고정 여부는 지금 있는 상태(예약)와 새 선택 칸(시각 고정) 하나로 판단.
- 한 번의 순서 바꾸기는 되돌리기 한 걸음(여러 일정의 시각이 함께 돌아감) — 되돌리기 쌓임에 「묶음」 걸음을 더한다.
- 저장: 일정에 선택 칸 `timeIsFixed`(없으면 키를 쓰지 않음). 호환 시험을 색·예상 지출 때와 같은 방식으로.
- 시험: 다시 잡기 계산(고정 건너뛰기, 겹침 없음, 하루 넘김), 묶음 되돌리기, 저장 호환.

### C4. 세부 계획 (중간~큼) — D1에 달림
- 코스의 곳을 누르면 그 줄이 펼쳐져 세부 줄(시각·이름)이 보이고 「세부 더하기」가 있다. 세부는 그 곳의 시간 안에 놓인다.
- 저장: 일정에 선택 칸 `parentItemID`. 없으면 굵은 곳. 부모가 지워지면 세부도 함께 지우고(되돌리기 가능), 부모 시각이 옮겨지면 세부도 같은 만큼 옮긴다.
- 계획표에서는 세부도 보통 칸으로 보이되 부모와 같은 색 테두리. 코스 목록과 지도 핀은 굵은 곳만 센다.
- AI 가져오기: 지금 형식(`bokki-trip`)에는 부모가 없으니 모두 굵은 곳으로 들어온다. 형식에 부모를 더하는 것은 뒤로.
- 시험: 부모 옮기기·지우기에 세부가 따라가는지, 저장 호환, 코스 번호가 굵은 곳만 세는지.

### C5. 지도 핀을 코스 모양으로 (중간) — D5
- 코스 탭일 때 핀: 지름 40 동그라미(그림 또는 종류 아이콘) + 아래 번호 배지 + 오른쪽 흰 이름표, 지금 곳은 테두리 굵게. 길은 실선.
- 핀이 겹치면 지금처럼 이름표는 가까운 것 하나만.
- 파일: `TravelStreetMap.swift`(핀 그리기를 모양 값으로 받게), `TravelModeView.swift`(모양 고르기 한 줄).
- 시험: 핀 모양 값 계산, 화면 시험 사진.

### C6. 사진 받아 오기 (큼) — D4
1. `TravelPlacePhotoStore`(새 파일): 일정 번호 → 그림. 순서는 찍은 사진 → 위키 → 없음(아이콘). 화면에는 지금 보이는 곳부터 차례로 하나씩 받는다.
2. 위키: 좌표 둘레 찾기 + 대표 사진 작은 크기(가로 320). 이름이 비슷한 항목만 채택. 사진의 작가·라이선스를 함께 받아 편집기와 사진 크게 보기에 표시.
3. (하지 않음 — 대표 결정) 주변 보기.
4. 캐시: 위키 사진은 `Caches/TravelPlacePhotos`에 일정 자리(좌표 4자리 + 이름) 이름표로, 총 30MB·오래된 것부터 지움·메모리 경고 때 메모리 쪽 비움. 백업에 들어가지 않는다.
5. 설정: 「여행 사진을 인터넷에서 받기」 스위치(끄면 ①·④만). 처음 켤 때 무엇이 나가는지 한 줄 안내.
6. 사용자가 직접 고른 사진으로 덮어쓰기는 이 단계에 넣지 않는다(저장 칸과 백업 처리가 필요 — 따로).
- 시험: 순서 고르기, 이름 비슷함 판정, 캐시 상한·지움, 받아 온 응답 읽기(저장해 둔 응답 파일로), 인터넷 없이 아이콘으로 떨어지는지. 실제 호출은 기기에서 후쿠오카·서울 각 5곳으로 재서 몇 곳이 나오는지 `test.md`에 적는다.

- TestFlight는 대표 지시가 있을 때 메인 세션이 올린다.

## 6. 순서와 크기

C1 → C2 → C3 → C5 → C6 → C4 → C7 → C8.

- C1~C3까지 하면 「코스 먼저」가 실제로 쓸 수 있게 된다(저장 칸은 C3의 하나뿐).
- C5·C6은 겉모습이다. C6이 가장 크고 바깥 서비스에 기대므로 확인 항목(4절)을 먼저 잰다.
- C4는 저장 칸과 규칙이 가장 많아 D1을 정한 뒤에 한다.

## 7. 위험과 대비

| 위험 | 대비 |
|---|---|
| 자동으로 잡은 시각이 사용자가 정한 시각을 덮는다 | 고정 칸과 예약 상태를 건너뛴다. 다시 잡기는 늘 되돌리기 한 걸음 |
| 위키 사진이 엉뚱한 곳 | 좌표 둘레 + 이름 비슷함 둘 다 맞을 때만. 편집기에서 「이 사진 쓰지 않기」 |
| 저작권 표시 누락 | 사진과 함께 받은 작가·라이선스가 없으면 그 사진을 쓰지 않는다 |
| 장소 이름·좌표가 바깥으로 나감 | 설정 스위치와 안내. 사용자 이름·기기 정보는 보내지 않는다 |
| 주변 보기가 한국에서 안 나옴 | 없으면 조용히 다음 순서로. 범위를 가정하지 않고 물어본 결과로만 판단 |
| 저장 칸 추가로 예전 빌드와 어긋남 | 선택 칸만 더하고, 예전 바이트 그대로·예전 모양으로 읽힘을 시험으로 입증(색·열 구성 때와 같은 방식) |
| `TravelModeView.swift` 줄 수 한도 | 새 코드는 다른 파일에. 단계마다 구조 점검 |
| 코스와 계획표가 서로 다른 말을 함 | 둘 다 같은 일정 목록에서 그린다. 코스 전용 저장은 만들지 않는다 |

## 8. 이 계획에서 하지 않는 것

- 시안의 자동 재생(가운데 재생 단추)과 「목차·소개·여행 정보」 탭.
- 스티커·Plan B(대표가 고르지 않음).
- Google Places, 우리 서버를 두는 사진 중계.
- AI 가져오기 형식에 세부 계획(부모) 넣기 — C4가 자리 잡은 뒤.
