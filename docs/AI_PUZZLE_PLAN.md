# AI와 「조각 맞추기」로 여행 일정 만들기 (AIT1116A01)

대표 지시(2026-11-16): 앱의 자랑은 「AI와 대화 → AI가 다듬어 올림 → 앱이 비주얼라이제이션」. 일정을 한 번에 통째로 받는 대신 **조각을 하나씩 맞춰 가는 느낌**으로 AI와 만든다. 시안: `design/AIT1116A01/preview.html`.

## 0. 먼저 알아 둘 것 — 이미 있는 것

- 여행 일정 칸에는 상태 `booked | planned | tentative(미정)`이 **이미 저장돼 있다**(`TripItemStatus`, 서버 `TRIP_STATUSES`). 미정은 지금도 반투명·점선으로 그려진다(`TravelPlanTable`). → **「조각」 = 미정 일정**으로 보면 저장 형식을 바꾸지 않고 시작할 수 있다.
- AI가 일정을 하나씩 올리는 도구도 이미 있다: `add_trip_item`(시각 있는 일정), `update_trip_item`, `delete_trip_item`, `set_trip_item_status`(`booked|planned|tentative`), `add_trip_stop`(지도 핀). 명령은 「AI가 한 일」에 남고 되돌릴 수 있다.
- **함정**: `add_trip_item`에는 `status` 칸이 없어 항상 계획(`planned`)으로 들어간다(`server/trip-relay/src/actions.js`). 미정으로 올리려면 ① 올린 뒤 `set_trip_item_status`를 한 번 더 부르거나(왕복 2번, 서버 변경 없음) ② 서버 도구에 선택 칸 `status`를 더해야 한다(작고 옛 앱과 호환되는 추가이나 **서버 배포 필요**). → 대표 결정(2026-11-16)으로 ②를 코드에 넣었다(아래 5절). 통째 계획 `send_trip_plan`(bokki-trip v1)의 일정에는 `status`가 이미 있다.
- `get_ai_tasks`는 앱이 AI에게 맡기는 일 목록이다(`AITaskQueue`, 종류 `other` 등). 글만 바꾸면 새 서버 종류 없이 「이 자리를 채울 후보를 찾아 주세요」를 올릴 수 있다.
- 레퍼런스 프롬프트(`TripImportPrompt`)는 「미정(tentative)은 확신 없는 후보」라고 이미 말한다.

## 1. 세 안

### (가) 조각 판 — 후보를 쌓고 끼운다

흐름: AI가 대화로 정리한 일정을 올리면 **끼워지는 것(확정에 가까운 것)은 날짜 칸에, 고르라는 것은 판 옆 「조각」 서랍에** 쌓인다. 조각은 모양(곳·식사·이동·숙소 아이콘)을 가진 카드. 사용자가 조각을 눌러 끌거나 「끼우기」를 누르면 날짜·시간 빈 칸에 들어가며 계획(`planned`)이 된다. 안 끼운 조각은 `tentative`로 남아 후보(점선)다. 빈 칸(점심·오후 자유 시간)은 퍼즐의 빈 자리처럼 점선 윤곽으로 보인다.

- 서버: **1차는 변경 없음**. 조각은 ⓐ `send_trip_plan`의 `status: tentative` 일정(지금 있는 길), ⓑ `add_trip_item` 뒤 `set_trip_item_status`로 올라온다. 끼우는 것은 앱 안 동작(`setTripItemStatus`와 같은 모델 함수)이라 서버를 거치지 않는다. 프롬프트에 「확정 안 된 것은 tentative로 올려 주세요」만 보강. 한 번에 올리게 하려면 `add_trip_item`에 `status` 선택 칸을 더한다(2차, 배포 필요).
- 저장: **변경 없음**(`status`만 씀). 새 화면 한 개(여행 화면의 「조각」 서랍·판)와 순수 계산(빈 자리·끼울 수 있는 자리 찾기).
- 크기: 중(새 파일 3~4개: 판 계산, 서랍 뷰, 끼우기 동작, 시험). 기존 `TravelModeView`엔 연결 몇 줄.
- 위험: 끌어 놓기가 작은 화면에서 어렵다(→ 「끼우기」 단추를 기본으로, 끌기는 보조). 일정이 많으면 서랍이 길다(날짜별 묶음).

### (나) 빈 자리 채우기 — 빈 칸을 눌러 AI에게 묻는다

흐름: 앱이 그날의 빈 시간(일정 사이 45분 이상)을 조각 모양 빈 칸으로 보인다. 누르면 「이 자리를 채울 후보를 찾아 주세요」(앞뒤 일정·시간·예산 요약, 좌표 없이 이름만)가 AI 확인 목록(`get_ai_tasks`)에 올라가고, AI가 후보 2~3개를 미정 일정(`add_trip_item` + `set_trip_item_status`)으로 돌려주면 그 빈 칸에 조각으로 나란히 나타난다. 하나를 고르면 끼워지고 나머지는 지워진다(되돌리기 가능).

- 서버: 새 종류가 필요 없다(`other` + 본문 글). 다만 AI가 그 일을 「이 빈 자리」와 맞추려면 일 본문에 `slot` 정보를 글로 넣는다. 정식 종류(`trip_gap`)는 서버 배포가 필요하니 2차.
- 저장: 변경 없음. 맡긴 일 목록은 이미 저장돼 있다.
- 크기: 중~대(빈 자리 계산 + 일 올리기 + 후보 묶음 표시 + 선택 시 정리).
- 위험: AI가 늦게 답한다(분 단위). 푸시가 꺼져 있으면 앱이 깨어날 때까지 지연. AI가 후보를 못 올리면 빈 칸이 계속 비어 있다(→ 「AI에 다시 묻기」). **AI 연결이 있어야 의미가 있다**(연결을 앞으로 둔 이유와 같은 방향).

### (다) 대화 한 턴 = 조각 하나 — 하나씩 딸깍

흐름: 레퍼런스 프롬프트를 고쳐, AI가 통째 JSON 대신 대화 한 턴마다 `add_trip_item`으로 하나씩 올리게 한다. 앱이 새 조각이 올 때마다 일정표에 「딸깍」 끼워지는 효과(짧은 미끄러짐·햅틱)와 「이 조각 빼기」(되돌리기)를 보인다. 사용자는 AI와 대화하며 일정표가 자라는 것을 곁눈으로 본다.

- 서버: 변경 없음(기존 도구). 프롬프트·도구 설명(`mcp.js`)에 사용법만 보강. 한 턴에 조각 하나를 미정으로 올리려면 `add_trip_item`의 `status` 칸이 있어야 매끈하다(코드에 넣음, 서버 배포 전까지는 왕복 두 번).
- 저장: 변경 없음.
- 크기: 소~중(프롬프트, 효과, 도착 알림). 가장 가볍다.
- 위험: 앱이 열려 있지 않으면 효과를 못 본다(열 때 한꺼번에 반영). AI가 한 턴에 여러 개를 올리면 순서가 섞인다. 한도(하루 편집 30건)에 걸린다.

## 2. 견주기

| | 가 조각 판 | 나 빈 자리 채우기 | 다 한 턴 = 조각 하나 |
|---|---|---|---|
| 「조각 맞추기」 느낌 | 가장 강함(고르고 끼움) | 강함(빈 칸이 퍼즐 자리) | 중간(자라는 느낌) |
| 사용자가 하는 일 | 고르고 끼움 | 빈 칸을 누름 | 대화만 |
| 서버 변경 | 없음 | 없음(정식 종류는 2차) | 없음 |
| 저장 변경 | 없음 | 없음 | 없음 |
| AI 연결 의존 | 올릴 때만 | 매번 | 올릴 때 |
| 크기 | 중 | 중~대 | 소~중 |
| 단독으로 완성되나 | 예 | 가에 얹는 것이 자연스러움 | 가에 얹는 것이 자연스러움 |

세 안은 겹친다: **가가 바닥(조각 = 미정 일정, 판·서랍)**, 다는 가의 「올라오는 순간」 효과, 나는 가의 「빈 자리」에 AI를 붙이는 것이다.

## 3. 권고

**가로 시작하되 다의 「딸깍」 효과를 같이 넣는다(1차). 나는 2차.**
1차(저장 형식 변경 없음): 미정 일정을 「조각」으로 모은 서랍 + 끼우기(미정 → 계획, 시간 겹침 확인) + 새 미정이 올 때 딸깍 효과 + 프롬프트의 「확정 안 된 것은 tentative」 보강.
2차: 빈 자리 계산을 판에 보이고 「AI에게 후보 묻기」, 서버 정식 일 종류 `trip_gap`(배포 필요).
설계만 하고 멈추는 것: 조각을 날짜 없이 여행에 붙여 두는 「날짜 미정 조각」(현재 일정 칸은 날짜가 필수라 저장 형식 변경), 조각 묶음·대안 그룹(`alternativeOf`), 스키마 v2의 `merge`/`baseRevision`.

## 4. 날짜 없는 조각의 한계(설계만)

「제주 올레길 걷기」처럼 날짜를 안 정한 후보는 지금 형식으로 둘 곳이 없다. 1차에서는 AI가 **가장 가능성 높은 날에 미정으로** 올리고, 사용자가 끼울 때 날짜를 옮긴다. 진짜 날짜 없는 조각을 지원하려면 여행 기록에 「조각 보관함」 칸을 더해야 하고(SQLite 스키마·백업 포맷 호환 입증 필요), 서버 `add_trip_item`의 `date` 필수 규칙도 바꿔야 한다. 대표 승인 뒤에 한다.

## 5. 1차로 넣은 것(2026-11-16)

- 여행 화면 계획 시트의 「조각」 서랍(`TravelPuzzleDrawer.swift`)과 순수 계산(`TravelPuzzle.swift`): 미정 일정 모으기, 시간 겹침 찾기, 새로 온 조각 알아내기. 「끼우기」는 미정 → 계획, 되돌리기는 다시 미정.
- 새 조각이 오면 튀어 들어오는 효과와 가벼운 진동(「딸깍」). 동작 줄이기 설정에서는 효과 없이 바로 보인다.
- 레퍼런스 프롬프트(`TripImportPrompt.swift`)에 「고르지 못한 후보는 각각 tentative로, 이야기하지 않은 후보는 지어내지 않기」 한 줄.
- `add_trip_item`의 선택 칸 `status`(`booked|planned|tentative`): 서버 `actions.js`·시험·기준표, 앱 `AssistantOperations+Plans.swift`·`AssistantActivitySync.swift`. 칸이 없으면 예전처럼 계획. **서버 배포는 대표 지시 뒤**이고, 배포 전에는 이 칸을 쓸 수 없으니 ⓑ 길(`set_trip_item_status`)로 올라온다.
- 저장 형식 변경 없음.
