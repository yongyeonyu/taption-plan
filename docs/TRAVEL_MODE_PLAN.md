# 여행 모드 개편 계획 (TVM1111A01)

2026-11-11 대표 지시를 모은 계획이다. 구현 전이다. 단계마다 새 요청 ID로 진행한다. Taption Trip 쪽 근거는 `docs/TRIP_PORT_ANALYSIS.md`에 있다.

## 1. 컨셉 (대표)

- 앱은 하나인데 여행 모드에 들어가면 완전히 다른 컨셉이 된다. 일상에서 받아오는 것은 AI와 돈뿐이다. 여행은 일상의 일부라서 여행 기록과 지출은 일상 기록 안에 남는다.
- 여행 모드는 여행하는 사람이 계획과 실제를 계속 비교하면서 기록을 완성하고, AI가 그것을 돕는 곳이다.
- 일상은 가계부다. 일본 여행 경비 100만 원이면 일상에는 그 한 줄만 있고, 여행 모드에 그 100만 원의 상세와 기록이 따로 있다.
- 여행은 여러 개를 구분한다(여행 목록 → 여행 하나). 국내 당일치기도 여행이다.

## 2. 화면 (대표 결정)

| 요소 | 내용 |
|---|---|
| 여행 목록 | 여행 카드(이름·기간·N박 N일 또는 당일), 새 여행. 오늘이 여행 기간이면 그 여행으로 바로 들어감(제안) |
| 시트 내림 | 전체 지도 + 오른쪽 사이드바. 사이드바는 계획 띠와 실제 띠 두 줄 |
| 시트 올림 | 위쪽 지도 + 아래 계획표. 계획표가 올라오면 사이드바는 사라짐 |
| 사이드바 ↔ 계획표 | 핵심. 같은 시간표의 접힌 모습과 펼친 모습이다. 보는 시각·줌·선택을 함께 쓴다 |
| 계획표 | 이동·식사·관광·숙소 열, 지금 시각 선, 끌어서 옮기기·길이 조절, WBS 스타일 선 연결 |
| 경로 구성 | 일정 사이 이동 수단(걷기·자동차·지하철·배 등)을 계획에 넣고 지도에 수단별로 그림. 실제 수단과 비교 |
| 메인 메뉴 | 여행 전용: 일정 추가, 빠른 지출, 계획표 올리기/내리기, AI, 재생 |
| 돈 | 게임처럼 화면 맨 위에 늘 보이는 표시줄: 원화·여행지 통화·달러·카드 네 칸(대표 지시, 별도 돈 화면이 아님). 둘째 칸은 가는 나라의 통화다(일본이면 엔, 태국이면 바트). 달러는 기축통화라 늘 있다. Taption Trip의 `TripCurrencyPolicy`(자국·여행지·달러 세 지갑)와 같은 방식. 예산 100만 원이 환전으로 칸에 나뉘고(20만 원 → 달러, 80만 원 → 엔화), 카드로 넘겨 쓰면 카드 칸이 마이너스가 된다(카드 -50만, 쓴 돈 150만). 일정마다 금액, 환전 기록, 동행 정산 |
| 날씨 | 계획한 장소·시각의 날씨를 보여 준다(내 위치가 아니라 일정이 있는 지역). 일차 칩에 그날 날씨, 계획표 일정 칸에 그 시각 날씨, 비 예보면 바깥 일정에 표시. 기존 `AppleWeatherContextService`(WeatherKit 시간별 예보)를 쓴다. 예보가 안 닿는 먼 날짜는 비워 둔다 |
| 재생 | 릴스처럼. 보일 것은 경로·사진(영상)·무엇을 했는지. 걸음 수·칼로리는 뺀다 |

재생 속도 규칙: 탈것 이동은 빠르게, 걸어다닌 구간과 사진 있는 곳은 느리게 해서 앨범처럼 다 보여 주고, 찍은 영상은 하이라이트 2~3초씩. 결과는 세로 한 편의 영상 클립.

## 3. 지금 코드에서 확인한 것

- `isTravelMode`는 저장하지 않는 `@State`이고(MapHomeView.swift:509), 바꾸는 것은 하단 바 내용, 날짜 하한, 사이드바 구간(계획으로 바꿔 그림), 가계부에 넘기는 여행 번호뿐이다. 지도 핀·경로·재생은 모드와 무관하게 그려진다.
- **여행이라는 덩어리가 없다.** 일정(`TravelTripItem`)과 핀(`TravelPlanStop`)에 `tripID`만 있고, 여행 제목은 저장되지 않는다. 이름이 남는 곳은 가계부 `LedgerTrip.name`뿐이다.
- 일정과 핀은 `AppFeatureSettings` 스냅샷 설정에 있다(SQLite 기록 아님). 일정 하나마다 `PlanRecord`도 만든다.
- **일정 시각·길이를 고치는 함수와 화면이 없다.** `PlanRecord` 쪽 `movePlan`·`resizePlan`만 있다.
- **계획과 실제를 비교하는 코드가 없다.** 사이드바는 여행 일정이 있는 날이면 기록 대신 계획을 그린다(`travelSidebarSegments ?? timeRailSegments`).
- AI 가져오기 JSON의 `travelFromPrevious {mode, minutes}`는 미리보기에만 쓰고 버린다. 이동 수단 목록은 자동 기록의 `TravelMode`(걷기·달리기·자전거·버스·지하철·택시·자동차·기차·비행기·배)를 계획에도 쓸 수 있다.
- 사이드바는 SwiftUI이고 시각↔좌표·줌 계산이 `MapHomeTimeSidebarMath`에 따로 있어 계획표가 같이 쓸 수 있다. 끌어 옮기기·늘이기·스냅의 본보기는 `MapHomeNLEClipEditor`.
- 지도를 위쪽으로 줄이는 자리는 `vectorMapContentInsets` 한 곳과 Apple 지도 `layoutMargins`.
- 재생: 하루 재생, 영상 내보내기, 구간 재생, 배경 음악 10곡, 사진 층(`MapHomePhotoLayer`)과 사진 권한이 이미 있다. 동영상 클립 합성 지원 여부는 확인 전이다.
- 가계부: 여행 장부·예산 이체·정산이 있다. 통화별 지갑과 환전 기록은 없다(기록 종류가 지출·수입뿐).
- 여행 모드 UI 시험과 접근성 식별자는 없다.

## 4. 구조 원칙

- 여행 모드는 일상 화면(`MapHomeView`)의 분기가 아니라 독립된 화면으로 세운다. 일상 화면의 배치는 건드리지 않는다.
- 여행 모드가 바깥과 닿는 통로는 셋이다: AI(같은 연결·확인 목록), 돈(같은 가계부), 자동 기록(읽기만, 계획과 비교할 실제).
- 순수 계산(비교, 연결선 경로, 지갑, 재생 순서)은 화면과 떼어 값 입력·값 출력으로 두고 단위 시험을 붙인다.
- 저장 형식이 늘어나는 단계는 옛 스냅샷·백업(TAPTBK03 쓰기, TAPTBK02 읽기) 호환을 시험으로 입증한다.
- 그리기 120Hz, 레이아웃 상태 60Hz 규칙과 기존 프레임 게이트(`TaptionInputFrameGate` 등)를 따른다.

## 5. 단계

| 단계 | 내용 | 저장 변경 | 선행 |
|---|---|---|---|
| T0 | 여행 단위 세우기: 여행(id·이름·기간·목적지) 저장, 가계부 여행 장부와 같은 id로 묶기, 당일치기, 일정 시각 고치는 함수 | 있음 | U2 |
| T1 | 여행 모드 껍데기: 여행 목록 → 여행 화면, 전용 메뉴, 일상 화면의 여행 분기 걷어내기 | 없음 | T0 |
| T2 | 사이드바 두 줄: 계획 띠 + 실제 띠, 어긋남 판정(없던 방문·건너뜀·밀림·수단 다름) | 없음 | T1 |
| T3 | 계획표 시트(보기): 분류 열, 지금 선, 사이드바와 상태 공유, 올리면 사이드바 숨김, 지도 위쪽으로 | 없음 | T2 |
| T4 | 계획표 편집: 끌어서 옮기기·길이 조절·스냅, 되돌리기 | 없음 | T3 |
| T5 | WBS 선 연결: 연결선 저장, 직각 경로 계산(Trip `TimelineConnectionRoute` 이식), 연결 편집 | 있음 | T4 |
| T6 | 경로 구성: 일정 사이 이동 수단·예상 시간 저장, 수단별 지도 경로(Apple 길찾기, 분석 문서 U8), 실제 수단과 비교 | 있음 | T3 |
| T6b | 날씨: 일정 장소·시각별 예보를 일차 칩·계획표·사이드바에, 비 예보와 바깥 일정 겹침 표시, 캐시는 지도 캐시 규칙(bounded) | 없음 | T3 |
| T7 | 돈 1: 예산 줄, 일정별 금액(계획·실제), 여행 중 지출 자동으로 여행 장부에, 일상 한 줄 → 여행 돈 화면 | 있음(계획 금액) | T1, U2 |
| T8 | 돈 2: 통화별 지갑과 환전 기록(분석 문서 U10), 카드로 쓴 돈 분리 | 있음 | T7 |
| T9 | 돈 3: 나누기 방식·환불 연결·정산 공유(분석 문서 U3~U7) | 있음 | T7 |
| T10 | AI: 어긋난 곳·빈 시간 채우기 제안, AI 확인 목록 연결, AI 명령에 일정 시각·수단 | 서버 포함 | T2, T6 |
| T11 | 재생 1: 여행 재생 화면(경로·사진·한 일), 속도 규칙, 건강 수치 빼기 | 없음 | T1 |
| T12 | 재생 2: 사진 앨범 구간, 영상 하이라이트 2~3초, 세로 영상 내보내기, 음악 박자 | 없음 | T11 |

순서 제안: U2 마무리 → T0 → T1 → T2 → T3(여기까지가 「사이드바 ↔ 계획표」 뼈대) → T7 → T4 → T6 → T5 → T8 → T11 → T12 → T9 → T10.

## 6. 대표 확인이 필요한 것

- 오늘이 여행 기간이면 목록을 건너뛰고 그 여행으로 바로 들어갈지.
- 다녀온 날을 나중에 여행으로 묶는 기능(당일치기)이 필요한지.
- 계획/실제 보기: 「계획만 / 비교 / 실제만」 세 가지로 둘지.
- 재생에서 사진을 바깥 AI로 보내지 않고 기기 안에서만 다루는 것으로 둘지.
- 「메인 메뉴」가 아래 메뉴 막대와 위 단추 줄을 뜻하는 게 맞는지, 항목 구성.
