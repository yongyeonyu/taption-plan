## 1. 핵심 방향성: "가운데 AI 버튼 + 서버 집중형 오케스트레이션"

1. **가운데 홈 버튼을 만능 음성 AI 입구로 전환**
   - 사용자가 가운데 버튼을 누르고 말하면, 앱이 **Apple 온디바이스 STT(`SpeechTranscriber`)**로 즉시 텍스트화(비용 0원)한 뒤, 의도에 따라 온디바이스 처리 또는 서버(`trip.bokkiyaw.com`) AI 게이트웨이로 라우팅한다.
   - 지원하는 핵심 음성·자동 액션:
     - **즉시 기록**: 메모 입력, 일정·리마인드 추가, 지출 가계부 입력
     - **기존 데이터 수정**: 음성으로 기존 활동명·이동 수단·일정 시간 수정
     - **자동 분류·교정**: 이동 수단 오분류(`route_check`), 결제 문자 분류(`payment_text`), 활동 구분
     - **능동 비서**: 시간대별 맞춤 말풍선, 일정·리마인드 제안
     - **검색·여행 플래닝**: 내 타임라인 검색, 지도/장소 검색, 대화형 여행 코스 생성
2. **API 직결이 아닌 서버(`trip.bokkiyaw.com`) 집중형 선택 이유**
   - 앱에 Bedrock/Azure/Algolia/Places 키를 직접 넣으면 키 유출, 무료·유료 쿼터 차단 불가, 모델 교체 시 앱스토어 재심사 문제가 발생한다.
   - 서버가 단일 관문(`/ai/command`)을 맡아야 **D1 기반 유저 맥락 조회 + 외부 도구 조합(Tool Calling) + 비용/쿼터 제어 + 오답 데이터 수집·학습**이 모두 가능해진다.

## 2. 2단 하이브리드 처리 구조 & 도구 라우팅

### 1단: 아이폰 온디바이스 우선 처리 (서버 원가 0원)
- **엔진**: Apple Intelligence(Foundation Models) + 로컬 규칙/정규식 + Apple MapKit
- **담당 작업**:
  - 음성 받아쓰기(`SpeechTranscriber`) 및 단순 메모/지출/일정 1차 파싱
  - 집/직장 반경 내 짧은 GPS 튐(자택 내 차량 오분류 등) 로컬 판정
  - D1에서 동기화된 **공통 가맹점·패턴 사전** 기반 즉시 분류 (0.01초, 서버 AI 미호출)
  - 단순 근처 장소 검색 (Apple MapKit 무료 사용)

### 2단: 자체 서버 AI 게이트웨이 (`trip.bokkiyaw.com/ai/command`)
- **호출 조건**: 1단에서 처리 불가한 복합 명령(여행 코스, 다중 일정/활동 수정, 맥락 질문), 온디바이스 미지원 기종, 또는 1단 신뢰도 미달 항목(모호한 가맹점명 등)
- **Worker + D1 오케스트레이션 흐름**:
  1. D1에서 `user_id`의 플랜(`free`/`pro`) 및 일/월 잔여 쿼터 확인
  2. D1에서 오늘 일정, 최근 활동/이동, 최근 메모, 개인 선호 요약(5~20ms SQL 조회)을 컨텍스트로 조립
  3. **AI 두뇌**: AWS Bedrock(우선, $1,000 크레딧) / Azure OpenAI(보조·이중화, $200~$5,000 크레딧) 경량·표준 모델 호출
  4. **외부 도구 Tool Calling 우선순위 (비용 방어)**:
     - 장소/콘텐츠 검색: **1순위 Algolia(월 1만 무료)** → **2순위 TourAPI(무료)** → **3순위 카카오/Google Places(일 30건 하드 캡 최후 보루)**
  5. 실행 결과(일정 JSON, 수정 patch, 응답 카드)를 앱에 반환하고, 사용자가 수정·거절한 내역은 학습용 로그에 기록

### 무료 사용자 차감 원칙 & 심사 가드
- **차감 ❌ (무제한 0원)**: 상단 키워드 검색, 가운데 버튼 단순 1건 기록(온디바이스 처리 성공 시), 로컬 사전/GPS 규칙 자동 보정, 오프라인 복귀 배치(1단 우선)
- **차감 ⭕ (무료 쿼터에서 1회 차감)**: 복합 자연어 질의·요약, 다중 일정/활동 일괄 수정, 여행 일정 생성, 2단 서버 AI 실제 응답 시 *(서버 오류·실패 시 미차감)*
- **리셋 & 심사**: 사용자 현지 자정(예: KST 00:00) 기준 리셋, 첫 AI 버튼 탭 시 제3자 AI 전송 및 비식별 패턴 학습 동의 고지 포함

### 다중 외부 에이전트 동시 연결 설계 (Pro 전용)
- Pro 유저는 `agent_tokens` 테이블에 **여러 외부 에이전트(피클, 클로드 코드, 개인 봇 등)를 동시에 등록**해 같은 D1 데이터에 병렬 접근 가능
- 동시 수정 충돌 방지를 위해 각 레코드에 `version`(낙관적 락)과 `updated_by_agt_id`를 기록하고, Webhook/MCP 실시간 Push 채널과 기존 `/tasks/claim` 폴링 채널을 모두 지원한다.

## 4. Claude API / `claude -p` 기반 야간 자동 학습 플라이휠 (오답 노트 시스템)

서버로 데이터를 모으는 가장 큰 장점은 **"쓸수록 정확해지고 서버 AI 호출 비용은 오히려 줄어드는 루프"**를 돌릴 수 있다는 점이다.

### 주의: 모델 파인튜닝이 아닌 "규칙·사전·프롬프트 자동 진화"
- Anthropic/Claude API는 가중치 파인튜닝을 제공하지 않으며 약관상 타 모델 학습용 추출을 금지한다.
- 대신 **D1에 쌓인 유저 수정 내역(오답 노트)을 Claude API / `claude -p`(월 $200 API 크레딧 활용 가능)로 야간 배치 분석**해 앱의 사전·로컬 규칙·시스템 프롬프트를 진화시킨다.

### 야간 학습 루프 동작 흐름
1. **피드백 수집 (D1 `ai_feedback_logs`)**:
   - 유저가 AI 분류 결과를 수정한 경우 (예: `동아웰빙타운관리단` → `주차장(transport)`, `지하철` → `자동차`)
   - 음성 명령 파싱 실패 / 재시도 로그
2. **비식별화 & 개인정보 가드**:
   - 야간 배치로 넘기기 전 **유저 식별자(이름·전화번호·상세 자택 주소·원문 카드번호 등) 제거/해시화**
   - 개인정보처리방침(동의 범위) 내 통계·가맹점 패턴 개선 용도로만 활용
3. **Claude 야간 분석 (`claude -p` 배치)**:
   - 반복 등장하는 가맹점명·오분류 패턴 추출 → **공통 가맹점/패턴 사전(D1 `merchant_rules` & 앱 배포 번들)**에 자동 등록 후보 생성
   - 자주 실패하는 음성 발화 패턴 분석 → **온디바이스 정규식·서버 시스템 프롬프트·Tool 스키마 개선안** 생성
4. **효과**:
   - 한 번 사전에 올라간 가맹점/패턴은 다음 유저부터 **LLM(Bedrock/Azure)을 안 부르고 0원·0.01초 만에 1단에서 즉시 정확히 분류**된다.

## 5. D1 스키마 및 서버 구현 체크리스트 (`taption-plan`)

1. **`user_ai_quotas` 테이블**: `user_id`, `plan`(`free`/`pro`), `daily_cloud_count`, `monthly_cloud_count`, `monthly_voice_sec`, `reset_at`
2. **`merchant_rules` 테이블**: `pattern`, `normalized_title`, `category`, `confidence`, `source`(`claude_nightly` | `manual`), `hit_count`
3. **`ai_feedback_logs` 테이블**: `user_hash`, `task_type`, `ai_output`, `user_corrected_output`, `anonymized_context`, `created_at`
4. **응답 규격 통일**: 한도 초과 시 `429 quota_exceeded` + `fallback: "on_device"` 반환, iOS 앱은 오류 팝업 대신 온디바이스 처리 후 자연스럽게 Pro 배지 안내
5. **기존 외부 에이전트 경로 보존**: `/tasks/claim`, `/command`는 `source: "external_agent"`로 유지해 내장 AI(`source: "built_in_ai"`)와 중복 실행 방지

## 6. 하단 바 개편: 메모 버튼 제거 + 가운데 AI 버튼 기반 메모 시나리오 (기존 기능 100% 유지)

하단 네비게이션에서 기존 오른쪽 **메모 아이콘을 제거**하고 가운데 버튼을 **AI 버튼**으로 전환하되, 기존 메모 기능(텍스트 직접 작성, 사진·위치·활동 연결, 목록 열람)이 전혀 불편해지지 않도록 상황별 진입 시나리오를 아래와 같이 설계한다.

### 상황별 메모 UX 시나리오 5종

1. **시나리오 A · 운전/이동 중 빠른 메모 (음성 우선)**
   - **동선**: 가운데 AI 버튼 **1회 탭** → 말하기 (*"방금 동아웰빙타운 주차 편했고 화장실 깔끔함 메모"*)
   - **처리**: 온디바이스 STT로 변환 후 현재 시간·위치·진행 중 활동에 자동 연결해 저장 (0원, 1~2초 내 완료 토스트)
2. **시나리오 B · 조용한 곳에서 손으로 적기 (회의·지하철)**
   - **동선 1 (가장 빠름)**: 가운데 AI 버튼 **길게 누르기(롱프레스)** → 음성 대기 없이 **기존 텍스트 메모 에디터** 즉시 오픈
   - **동선 2**: AI 버튼 탭 후 바텀 시트 우측의 작은 **`[✏️ 직접 쓰기]` 칩** 탭 → 기존 메모 에디터(키보드, 사진 첨부, 태그 선택 등 기존 UI 그대로)로 전환
3. **시나리오 C · 특정 활동/이동에 메모 붙이기 (타임라인 열람 중)**
   - **동선**: 타임라인의 특정 활동·이동 카드를 **탭(상세 진입) 또는 스와이프(`[+ 메모]`)** → 해당 활동의 시간·장소 ID가 자동 바인딩된 상태로 기존 메모 에디터 오픈
4. **시나리오 D · 대충 적은 메모의 자동 정리 (기존 기능 강화)**
   - 사용자가 직접 타이핑한 거친 메모도 저장 시(또는 `[다듬기]` 탭 시) 1단 온디바이스 / 2단 서버 AI가 오탈자 정리·활동 매칭·지출/일정 분리 제안을 제공 *(원본 텍스트는 항상 보존)*
5. **시나리오 E · 전체 메모 모아보기 및 편집**
   - 하단 메모 아이콘은 빠지지만, 기존 메모 목록·검색·필터 화면은 **상단 헤더 아이콘 또는 타임라인/검색 탭 내 필터**에서 그대로 접근 가능하도록 유지해 기존 사용자의 학습 혼란을 방지한다.

## 7. 컴팩트 하단 미니 채팅 시트 UI 규격 (가운데 AI 버튼 탭 시)

가운데 AI 버튼을 눌렀을 때 전체 화면을 덮지 않고, 사용자가 보던 **타임라인·지도를 그대로 보면서 대화할 수 있는 하단 미니 채팅 시트**를 기본 UI로 채택한다.

### 레이아웃 & 공간 배분
- **기본 높이 (Compact Mode)**: 화면 하단 **약 25~35% (예: `~240–280pt`)**만 점유 (`SwiftUI .presentationDetents([.height(260), .large])`)
- **배경 인터랙션 유지**: `.presentationBackgroundInteraction(.enabled)` 적용 → 채팅창이 열린 상태에서도 위쪽 65~75% 영역의 타임라인·지도 스크롤 및 활동 카드 탭 가능 (예: *"방금 누른 이 일정 옮겨줘"* 같은 맥락 연동)
- **확장/닫기**: 여행 코스·긴 검색 결과를 볼 때만 상단 그랩 핸들을 위로 드래그해 `.large` 모드로 확장, 아래로 스와이프하면 즉시 닫힘

### 시트 내부 구성 (위 → 아래)
1. **상단 미니 대화 스트림**: 최근 2~3턴의 사용자 발화 말풍선(우측) + AI 응답 말풍선(좌측)만 컴팩트하게 스크롤. 일정 수정·지출 등록처럼 반영이 필요한 응답은 말풍선 아래 **1줄 액션 칩(`[적용]` / `[취소]`)**만 간결하게 표시
2. **하단 단일 입력 바**: `[🎤 말하기(기본)]` · `[메시지 입력...]` · `[✏️ 메모로 바로 저장]` 버튼 1줄 배치 (텍스트 입력 시 마이크 버튼이 전송 버튼으로 전환)

## 8. 상단 통합 검색 (지도 + 내 전체 기록) AI 엔진 일원화

기존 상단의 **지도 검색창을 통합 AI 검색(Universal Search)으로 확장**하여, 가운데 AI 버튼과 동일한 온디바이스 + 서버 D1 검색/추론 파이프라인을 공유한다.

### 한 번의 검색으로 동시 조회되는 6대 영역
1. **지도/장소**: Apple MapKit(무료) + Algolia(월 1만 무료) + TourAPI(무료) *(Places는 최후 보루)*
2. **일정 · 달력**: 예정 일정, 리마인드, 캘린더 이벤트
3. **활동 · 이동 이력**: 과거 방문 장소, 이동 수단(`car`/`subway`/`walk` 등), 체류 시간
4. **메모**: 직접 작성한 메모 및 음성 메모 본문/태그
5. **가계부(지출)**: 가맹점명, 카테고리, 금액, 결제 날짜
6. **자연어 질의(AI 요약)**: *"지난달 주차비 얼마 썼지?"*, *"지난주 토요일에 간 카페 이름이 뭐였지?"* 같은 복합 질문

### 비용 0원 방어 원칙 (키워드 vs 자연어 자동 분기)
- **단순 키워드 검색 (Free 무제한 · AI 비용 0원)**:
  - 상단 검색창에 `"부평 주차장"`처럼 단어를 치면 → 로컬 SQLite / D1 `FTS5` 전문 검색 + Apple MapKit을 병렬 실행해 **[내 가계부] · [내 이동 이력] · [내 메모/일정] · [지도 결과]**를 섹션별 카드로 즉시 노출 (LLM 호출 없음)
- **자연어·복합 추론 검색 (2단 AI 라우팅)**:
  - 문장형 질의(집계, 조건 필터, 추론)를 입력하거나 `[✨ AI에게 물어보기]`를 탭하면, 가운데 AI 버튼과 동일한 **D1 컨텍스트 + Bedrock/Azure 게이트웨이**가 합산·요약 답변과 관련 원본 카드를 함께 반환 (Free/Pro 쿼터 규칙 동일 적용)

## 9. 대화형 다일 여행 일정 원스톱 가안(Draft) 생성 시나리오

사용자가 가운데 AI 버튼 또는 연결된 외부 에이전트(피클 등)에게 자연스러운 대화로 여행 계획을 요청하면, 항공·이동·숙소·방문 스팟을 **가안(Draft) 일정 블록**으로 한 번에 타임라인에 생성한다.

### 예시 발화
> *"다음 달 12월 12일 1박 2일로 일본 쇼핑 여행 일정 잡아 줘. 비행기는 김포 출발 일본 도착으로 아무거나 일단 넣어서, 새벽에 갔다가 저녁에 오는 일정으로 해 줘."*

### 처리 흐름 (서버 AI Tool Calling + D1 / 캘린더 반영)
1. **의도 및 제약 조건 추출**:
   - 기간: `2026-12-12 ~ 2026-12-13` (1박 2일)
   - 출발/도착 조건: `김포(GMP) 출발 → 일본(예: 하네다 HND / 간사이 KIX 등 목적지) 도착`, `가는 편 새벽/이른 아침 · 오는 편 저녁`
   - 목적: 쇼핑/여행
2. **항공·장소 블록 조립**:
   - 항공편이 확정되지 않았으므로 `is_draft: true` 상태의 **임시 항공 블록**(예: `[가안] 김포 → 도쿄 새벽 출발`, `[가안] 도쿄 → 김포 저녁 귀국`) 생성 (향후 항공편 API/예약 확정 시 해당 블록만 교체 가능)
   - Algolia / TourAPI / MapKit을 조합해 1일차·2일차 동선(공항 이동, 쇼핑 스팟, 식사, 숙소 체크인/아웃)을 시간대별로 배치
3. **사용자 확인 카드 & 원클릭 반영**:
   - 미니 채팅 시트에 1박 2일 타임라인 프리뷰 카드 노출 → 사용자가 `[일정에 가안 넣기]` 탭 시 D1 일정 테이블에 일괄 저장 (`draft` 배지 표시)

## 10. 중복 방지 · 16자리 고유 ID 규격 · 외부 AI 결과 포함 암호화 학습 & 대시보드 연동

내장 서버 AI와 다중 외부 AI 에이전트가 동시에 붙어도 중복 실행·덮어쓰기가 발생하지 않도록 하고, 외부 AI의 우수 처리 결과까지 비식별·암호화하여 내장 AI 학습 및 운영 대시보드에 반영한다.

### A. 16자리 영숫자 고유 ID 체계 (충돌 방지 · 멱등성)
- **생성 규칙**: 혼동 문자(`0/O`, `1/l/I`)를 제외한 Base58/영숫자 16자리 + 접두사
  - `usr_{16자리}`: 사용자 고유 ID
  - `agt_{16자리}`: 에이전트 고유 ID (`built_in_ai` 또는 Pro 유저의 외부 에이전트별 개별 발급)
  - `req_{16자리}`: 개별 작업/요청 멱등성 ID (D1 `UNIQUE` 제약으로 동일 이벤트 중복 생성 차단)

### B. 중복 처리 방지 3대 안전장치
1. **소유권 라우팅 + 타임아웃 폴백**: 외부 에이전트가 연결된 유저의 백그라운드 태스크는 `external_agent` 우선(`pending_external`)으로 대기하고, 설정 시간(기본 10분, 대시보드에서 가변 조정) 내 미응답 시 내장 서버 AI가 자동 폴백 처리
2. **D1 원자적 선점 락**: `UPDATE tasks SET status='claimed', owner_agt_id=? WHERE req_id=? AND status='pending'` 단일 쿼리로 먼저 도착한 AI 1개만 선점 성공
3. **완료 잠금 + 낙관적 락**: `done` 상태 및 `version` 체크를 통해 이미 처리된 항목을 다른 AI가 재처리·덮어쓰기하는 것을 차단 (유저의 명시적 재요청 시에만 예외)

### C. 외부 AI 처리 결과까지 포함하는 암호화 학습 & `BOKKI 운영` 대시보드 연동
1. **이중 학습 소스**: 내장 AI 오답 노트뿐 아니라, **외부 AI(`agt_...`)가 처리 완료한 결과(예: 모호한 가맹점명 정규화, 이동 오분류 교정 패턴)**도 모범 사례로 함께 수집
2. **비식별화 & 암호화 저장**:
   - 학습 로그 적재 전 개인식별정보(이름, 전화번호, 상세 자택 좌표/주소, 카드번호 등) 제거 및 `user_hash` 단방향 해시 치환
   - 원문 패턴은 **암호화(AES-GCM 등)하여 D1 `ai_learning_events` 테이블에 보관** *(개인정보처리방침에 서비스 개선용 비식별 패턴 학습 고지 포함)*
3. **야간 분석 & `BOKKI 운영` 대시보드(`tools/admin-console`) 반영**:
   - 야간 Claude 배치(`claude -p`)가 암호화 로그를 복호화·집계해 **신규 가맹점 사전 후보, 오분류 감소율, 외부 AI vs 내장 AI 처리 현황**을 요약
   - `BOKKI 운영` 콘솔에 **[AI 현황 · 학습]** 탭을 추가해 처리 건수·정확도 추이·신규 자동 규칙 승격 목록을 실시간 확인 및 원클릭 반영 가능하게 구성

## 11. `BOKKI 운영` 대시보드 동적 운영 레버 (초반 적극 개입 ↔ 성장기 부하 분산)

초반에는 외부 에이전트를 연결하지 않은 유저가 많고 확보된 AI 크레딧(AWS $1,000 · Azure $200~$5,000 · Claude $200)에 여유가 있으므로, 코드 배포 없이 **`BOKKI 운영` 대시보드(`tools/admin-console`)에서 운영 정책을 실시간 조절**할 수 있도록 D1 `system_ai_config` 테이블과 제어 UI를 둔다.

### 대시보드 실시간 제어 항목
1. **내장 AI 개입 적극도 / 티어별 쿼터 실시간 조정**:
   - 초반 성장기: 무료 웰컴(`일 15회`), Pro 기본(`월 100회`) 또는 프로모션 상향 조절
   - 사용량 급증 시: 서버 AI 쿼터를 보수 모드로 낮추고 1단 온디바이스 · 외부 에이전트 비중 자동 확대
2. **외부 에이전트 ↔ 내장 AI 우선순위 & 폴백 타임아웃(기본 10분)**:
   - 기본 `10분` 무응답 시 내장 AI 폴백 → 대시보드에서 `3분` / `10분` / `30분` 또는 `내장 AI 즉시 우선` 모드로 전환 가능 (사용자가 답답해하지 않도록 체감 속도 조절)
3. **크레딧 소진 현황 & 학습 ROI 모니터**:
   - 유저/외부 에이전트 간 처리량, 크레딧 소진 속도, 야간 학습을 통해 1단(0원 로컬 규칙)으로 승격된 비율을 대시보드에서 통합 관제
